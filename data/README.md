|----------|-------|

| Target | `is_rto` (1 = RTO, 0 = delivered) |

## Data Generation Methodology

All data is **synthetically generated** using `src/data_generator.py`.

**No real customer data, no real Razorpay internal data, no PII.**

The generator encodes realistic relationships via a logistic-regression-style data-generating process (DGP):

```
logit(p_rto) =
    intercept                                        # ~14% base RTO rate
  + 1.3  × is_cod                                   # COD: strong positive signal
  + 2.5  × customer_rto_rate                        # repeat RTOs: strongest signal
  + 1.2  × (1 - address_completeness / 100)         # bad address
  + 1.0  × pincode_rto_rate                         # bad pincode
  + 0.5  × log(1 + orders_last_7_days)              # high velocity
  + 0.4  × max(current_vs_avg - 2.0, 0)            # order value spike
  + 0.35 × is_festival_period                       # festival noise
  - 0.7  × log(1 + previous_delivered_orders)       # proven delivery history
  - 0.4  × (customer_age_days / 365)               # customer maturity
  + 0.3  × (location == RURAL)
  + 0.2  × (location == TIER2)
  + noise ~ N(0, 0.9)                               # realistic overlap
```

`is_rto ~ Bernoulli(sigmoid(logit))`

## Feature Leakage Audit

Every feature is available **at fulfillment decision time** (i.e., before the order is dispatched).

The following columns are **NOT** in the dataset because they would leak future information:

| Excluded Column | Reason |
|----------------|---------|
| `delivery_outcome` | Reveals future |
| `rto_date` | Reveals future |
| `return_reason` | Reveals future |
| `final_delivery_status` | Reveals future |
| `num_delivery_attempts` | Reveals future |

## Train / Validation / Test Split

A strict **time-based split** is used. No random shuffling across time boundaries.

```
Jan 2024 ──────────────────────────────────── Jun 2025
│                                                    │
├─── Train (70%)  ────┤─── Val (15%) ──┤── Test (15%) ─┤
 Jan 2024 – Nov 2024    Nov 2024–Feb 2025  Feb–Jun 2025
```

The **test set is locked** — it is evaluated exactly once using the threshold
selected on the validation set. No re-tuning after seeing test metrics.

## Reproducibility

